# Endgame Convergence：附庸与觉醒

2026-10-07 本轮已有原生依据：同一文明零城/零单位存活、真实推进回合、归档存读档、城市归还、首都/宫殿，以及人类原勇士队列和4点产能恢复；待确认生产事务重载后完成，重复执行不重复追加。入口、配置、证据和限制见[本轮验收](../Civ6_GrandCampaign_Research/docs/46-native-completion-20261007.md)。完整项目尚未交付。

新独立单人测试局可选 `EC_NATIVE_VASSAL_TEST=1`，同时关闭 `EC_OBSERVATION_ONLY`，开启 `EC_METRIC_BRIDGE_TEST`、`EC_ELIGIBILITY_OBSERVATION_TEST` 和 `EC_WAR_OBSERVATION_TEST`。新模式会在建局时加载归档存活规则，旧观测存档不能只改开关升级；所有开关默认关闭，当前仅作独立测试。

正常玩法源码已绑定资格→真实附庸事务→项目/自治→复国事务。四领域优势、持续时间、战争关键胜利和保护状态在提交前再次核验。总览提供对应请求/项目切换/自治达标复国按钮；人类接受与拒绝使用独立的真实请求 token，演练确认不能授权真实事务。生产由宗主重新安排，原队列和产能归档暂停；复国要等原生队列和产能读回后才完成。标准事件路径正在原生验收，按钮或源码加载不能视为通过。

当前仅本地人类首项产能恢复有原生证据；AI有生产记录及历史未激活产能会在城市变更前拒绝，需继续补齐。觉醒/真实胜利、Stability全项及大地图联动仍待完成。下面的旧研究说明保留背景，以本段、PROJECT与验收文档为当前状态。

游戏内名称为“后期终局：附庸与觉醒”。`Civ6_GrandCampaign_Research` 文件夹只保存文档和离线测试，没有 `.modinfo`，不需要在游戏里启用。2026-10-03 已修复翻译 XML 缺少语言字段导致的加载失败；19 个高级设置及说明、附庸确认弹窗全部提供简体中文与英文备用文本，可在游戏内停用再启用模组刷新文本，返回高级设置确认界面。详情见 [本地化修复记录](../Civ6_GrandCampaign_Research/docs/18-localization-audit-20261003.md)。

终局研究模组。默认观测主要文明实力、存活数量、灭国比例和时代触发，不执行真实附庸、城市转移、宣战或胜利修改。项目 modifier 效果由 `EC_PROJECT_EFFECTS_TEST` 单独控制，默认关闭；影子附庸或觉醒干跑也不会自动开启它。

默认关闭的 `EC_AWAKENING_ACTIONS_TEST` 在明确单人、关闭观测、启用觉醒并关闭干跑的 `LIVE_TEST` 组合下，已有实际 modifier/宣战调用入口；原生战争、收益和胜利保护仍未验收。代理不启动或操作游戏；用户自行完成的小地图测试及接口修复见 Research 的最新审计。

评分指标来自原版 UI 已使用的玩家 API：军事力量、科技产出、文化产出、净黄金产出和城市数。净黄金按 `GetGoldYield() - GetTotalMaintenance()` 计算；维护费未知时整行不作为完整实力，负净收入合法。每 5 回合采样一次，按当前存活主要文明的最大值归一化后输出综合 Power。设置项预留了工业时代、最低回合和 30% 灭国比例，但 `EC_AWAKENING_ENABLED` 默认关闭。

本模组与 `Civ6_GrandCampaign_Stability` 独立，便于单独测量回合开销。真实附庸必须等零城市存活和指定城市归还 API 验证通过后再实现。开启 `EC_API_PROBE` 只输出城市、玩家和胜利相关接口存在性以及当前城市数，不调用城市转移或胜利修改。

左上角科技、文化、伟人、气候和总督所在工具栏末尾新增“附庸”入口，按 Haikesi 和原版 LaunchBar 已验证的入口模式追加到共享 ButtonStack，不覆盖 LaunchBar，也不挪动其他模组按钮。入口使用原版 49×49 背板和 35×35 城邦图标，悬停显示“附庸总览”，避免与其他模组文字按钮互相挤压。总览入口和面板分别沿用已被游戏识别过的 `EC_OverviewLaunchUI`/`EC_OverviewPanelUI` action ID，使用 `LoadOrder=30000/30001` 尽量排在常见第三方入口之后；共享 ButtonStack 已存在时立即追加自己的实例，避免较晚 action 错过一次性 `LoadGameViewStateDone` 后永久等待；工具栏尚未就绪时仍由载入、核心刷新、本地回合、视觉恢复和有限 `SystemUpdateUI`/`LoadScreenClose` 重试。总览显示已接触文明的影子附庸、宗主、自治度、项目截止回合及觉醒状态；观测局显示空档案是正常的。当前总览只读，未知字段显示“暂不可用”，真实附庸/复国操作未接通。当前总览 UI 47 项、确认弹窗 19 项、统计桥 15 项行为用例通过；共享模型导入暂不可用时会降级显示只读空态，实例创建或共享尺寸通知失败时会回滚自身控件并恢复共享背景尺寸，实际布局和多模组并排仍需用户确认，见 [工具栏总览与测试顺序](../Civ6_GrandCampaign_Research/docs/20-vassal-overview-20261003.md)。

`EC_SHADOW_VASSAL_TEST` 是更进一步的 opt-in 测试：它只写玩家 Property 形式的影子档案，让最多 `EC_SHADOW_VASSAL_LIMIT` 个较弱 AI 在每个项目周期自主选择支持或削弱宗主，并累积自治度；不会转移城市、删除单位或附加实际效果。项目周期以标速 5 回合为基准，并按 `GameSpeeds.CostMultiplier` 放大慢速周期。

影子项目现在每个周期重新评分，使用持久化测试倾向、当前实力差距、军事控制和自治度；同一周期可以同时存在支持与反对的附庸，不固定交替。支持选择宗主相对较弱的军事/经济/科技/文化方向，削弱选择相对较强方向。倾向由玩家 ID 确定，只用于可重复的研究测试，不代表原版领袖人格。评分权重待实际平衡测试；数据未知时不建立档案或作新选择，已完整暂存的选择在读档/故障重试时保持原样。旧版在途项目先结算，再采用新策略。

开启 `EC_PROJECT_EFFECTS_TEST=1` 且关闭观测模式后，项目会按支持/削弱和方向向宗主附加 modifier：军事为军队生产，经济/科技/文化为对应城市产出。同一宗主的每种效果最多累计 3 次，所有附庸共享限额；达到上限写 `CAPPED`，自治度仍正常增长。先保留限额并写 `PENDING`，成功后写 `APPLIED`；原生结果不确定时保留占用、写 `UNKNOWN` 并停止项目，避免重复发放。旧存档已有无法计数的效果时暂停，不自动叠上新限额。该路径仍是研究开关，必须验证原生产出、读档和速度平衡。

观测模式必须明确为 false 才能启用影子、确认、干跑和项目效果；未知配置不授权写入。影子自治到 100 后停止新周期，正常从 0 开始的档案最多结算 10 次项目；已暂存的提交仍可恢复，实际效果受宗主共享限额约束。此前附加的 modifier 会保留，原生清理与最终叠加数值尚未验证。

速度优先使用原版 `GameConfiguration.GetGameSpeedType()`：标准、史诗、马拉松周期分别为 5、8、15 回合。实力仍每 5 回合采样，项目期限逐回合检查；速度未知则暂停项目，不假设标准速度。项目先保存下一结果和 token，再发布字段及完成标记，读档/写入失败重试不重复增加自治度。

`EC_AWAKENING_DRY_RUN` 是独立的 opt-in 状态机测试：在关闭观测模式后，它把觉醒触发、AI 候选、准备期、征服期和决战期写入玩家属性，支持保存/读档恢复；不会宣战、附加 modifier、改变胜利或保护任何文明。

觉醒 payload、版本、模式和阶段标记持久化；同一回合读档不额外推进阶段。最早回合、准备期与征服期统一随游戏速度缩放，默认最早回合为标准 120、史诗 180、马拉松 360。动作实验的准备期先附加生产/军备加成，征服期再附加战斗/经济，决战期再附加科技/文化；旧六项加成记录不重复附加。总览显示下一阶段的预计回合与剩余回合，未接触的文明保持匿名。候选死亡、失去所有城市、变为玩家或附庸时结束流程，未知身份/状态暂停。后期首次启用优先通过历史主要文明列表恢复固定槽位普通局的分母；拿不到历史记录时不猜测开局数量，暂停灭国比例触发，时代触发仍可测试。动态加入新文明的场景需要单独验证。系统续查见 [文档45](../Civ6_GrandCampaign_Research/docs/45-system-review-and-pacing-20261007.md)。

正式规则允许玩家和 AI 都成为附庸，但玩家城市移交前必须确认。当前影子测试只自动建立 AI 附庸档案。未知档案占用容量且不被覆盖。

`EC_PLAYER_CONSENT_TEST` 默认关闭，关闭观测模式后为每位明确的人类玩家创建一次确认演练请求，以当前最强的存活 AI 作为测试宗主，不检查正式附庸实力/战果资格。原版样式弹窗提供接受、拒绝和稍后决定；Enter/Escape 拒绝，只有显式点击接受才发送确认。请求有效期为标准/史诗/马拉松 5/8/15 回合，稍后决定允许关闭弹窗后保存，读档重显 pending 请求。

UI 用原版黑死病场景的 `EXECUTE_SCRIPT` 通道发送选择；Gameplay 核对实际发起玩家、目标、宗主、token、期限和文明状态。未知版本/模式只读，重复回调和过期响应不能改变结果。测试接受只写 `ACCEPTED_DRY_RUN`，不会移交城市、删除单位，也不能授权将来的真实附庸。真实移交与玩家确认 UI 的原生渲染、保存/读档、消息通道尚待小地图验收。

总览面板还会只读显示 `EC_ADVANTAGE_` 双缓冲资格观察：有效候选、失效候选和损坏记录分别标注，并在底部显示真实事务 adapter 尚未接通。候选显示不等于附庸授权，面板不会提交城市、单位或玩家变更。

MCP 提供本地只读 `GET /api/test/endgame-capabilities`，用于在后续游戏检验前清点 `CityManager`、`UnitManager`、玩家集合和属性 API 是否存在。能力探针不调用变更方法；即使返回能力齐全，也必须先完成 adapter 参数/结果语义验证，面板仍保持事务按钮关闭。

`GamePlay/EC_Eligibility.lua` 已作为可导入规则库加入，提供四项附庸差距、经济现金流/储备计算和连续优势观察。普通门槛为军力 2 倍、其余 1.5 倍，并要求本次战争内的近期关键战果；压倒性为军力 4 倍、其余 3 倍，可直接形成请求候选。保护未知/有效、科文进度落后、数据缺失和时间不可靠均阻止候选；玩家目标始终需要确认。该模块不读引擎、不写属性；默认关闭的 Gameplay 资格观察会通过 Observer 调用它，但不授权城市移交。

社区 API 索引将军力统计和已完成科技/市政计数标为 UI 方法。`EC_API_PROBE` 已增加 `api_probe_metric_context` 方法存在性记录，不能把方法存在当作 Gameplay 调用成功；可信快照接入仍需验证。未知实力数据现在也不能选为新觉醒候选。

`EC_METRIC_BRIDGE_TEST` 默认关闭、仅限已确认的单人环境。UI 在本地玩家活动回合采集军力、科技/市政计数、科文产出、净黄金、储备和城数，首次加载及每 5 回合边界提交一次。Gameplay 核对实际唯一人类发起者、回合、速度、身份和城数；完整记录双缓冲保存后，后续观测优先使用不超过 5 回合的快照。失败或未知值不默认成零，不完整条目也不参与 Power 归一化。

`EC_DataStore` 同时提供标量化的优势记录读写，保留上一份完整记录直到新记录发布。优势、战果和首都距离保护名单已有默认关闭的观察入口；真实原生消息通道、Getter 调用、保存/读档及性能仍待小地图验证。单人能力或本地活动回合接口未知时暂停，不支持多人或热座。

`EC_ELIGIBILITY_OBSERVATION_TEST` 默认关闭。开启它、`EC_METRIC_BRIDGE_TEST` 和观测模式后，Gameplay 在完整单人快照更新时调用 `EC_EligibilityObserver.Update`，自动保存连续优势/战争证据；保护状态未知时返回阻止，玩家/AI 请求、城市转移、单位处理和 modifier 都不会发生。它仍依赖真实 UI 快照、外交/城市所有权和 `.Civ6Save` 原生验证。

`EC_DEBUG_TIMING` 默认关闭。开启后记录终局快照、战争对采样和资格观察的有界耗时、文明数量和对象数量；日志只用于性能基线，不改变预算或玩法。

`EC_WarContext` 和 `EC_EligibilityObserver` 现在提供战争证据切片：记录 `CityConquered` 坐标、当前战争 session、和平重置、最多 64 城上限，并在资格判断前重新查询城市所有权。默认不绑定事件；开启 `EC_WAR_OBSERVATION_TEST` 且保持观测模式时，Gameplay 每次快照最多检查 256 对主要文明的对称战争状态，并绑定 `GameEvents.CityConquered`。该路径只写战争证据、遇到未知就停止，不宣战、不转移城市、不生成附庸请求；真实保护输入、资格生产者和原生保存/读档仍待验证。

`EC_Protection` 是纯保护判断：准备期/征服期保护玩家及最近 1 或 2 个 AI，决战期解除；保护附近列表不完整时返回未知并阻止资格。列表条目必须是明确存活、主要、独立且非玩家/非觉醒者的 AI。纯库不读取地图、不判断距离、不改外交；Gameplay 已提供首都距离名单并接入觉醒观测/动作入口，原生验证未完成。

研究仓库的最新离线回归以其 README 和 `tests/README.md` 为准，不能代替 Civ VI 原生保存/读档和引擎测试。完整审计与追加修复见研究仓库 `docs/16-full-audit-20261003.md`、`docs/17-api-contract-audit-20261003.md`；详细规则与数据流程见 `docs/10-project-policy.md`、`docs/11-vassal-eligibility.md`、`docs/12-snapshot-persistence.md`。

`GamePlay/EC_VictoryPolicy.lua` 是默认不绑定原生事件的胜利保护契约：准备/征服阶段阻止觉醒者获胜，决战阶段放行，显式 adapter 的读取、写入和验证任一步未知都会停止。它只用于离线接口验证；`EC_API_PROBE` 仍不调用 `Game.SetVictoryValid`，真实胜利事件、玩家级限制能力和存档恢复尚待原生探针。

`GamePlay/EC_AutonomyPolicy.lua` 是复国前置策略：自治度达到目标、档案完整、单位已移除、宗主和附庸仍有效且没有未决项目时生成稳定的复国授权；玩家档案还需要确认。它只生成 DTO，不调用城市、单位或玩家 API，随后由 `EC_VassalTransaction` 的显式 adapter/journal 契约负责原生操作。

附庸事务现在校验城市/单位密集清单和每项操作，并将完整计划签名存入 journal。相同 token 的不同计划、缺少签名的旧 journal 或结果不明的未完成操作保持只读；即使 UNKNOWN 写入失败也不再次执行原生操作。该接口仍没有 Gameplay 事件绑定。
